Ниже — **структурированный и приземлённый план**, ориентированный именно на защиту ВКР/курсовой, а не на «идеальный продакшен». Я сознательно разделяю **что взять**, **как связать** и **какой минимум реально защитить**.

# 1. Подбор конкретных репозиториев

## 1.1 Видео: выражения лица

### ✅ OpenFace 2.2

**Назначение:** извлечение интерпретируемых признаков (Action Units, gaze, head pose)

* Репозиторий:
  [https://github.com/TadasBaltrusaitis/OpenFace](https://github.com/TadasBaltrusaitis/OpenFace)
* Выходные данные:

  * AU01–AU45
  * confidence
  * timestamp
* Почему брать:

  * стандарт де-факто в исследованиях;
  * легко объяснить на защите;
  * не требует обучения.

**Использование:**
→ признаки → агрегация → эмоции / стресс

---

### ✅ AffectNet (CNN, предобученная)

**Назначение:** классификация базовых эмоций по кадрам

* Репозитории:

  * [https://github.com/omar178/Emotion-recognition](https://github.com/omar178/Emotion-recognition)
* Модель:

  * ResNet-50 / VGG16
* Статус:

  * веса предобучены
  * дообучение необязательно

**Использование:**
→ softmax эмоций → временная агрегация

---

## 1.2 Аудио: эмоции речи

### ✅ Wav2Vec 2.0 (SpeechBrain)

**Назначение:** эмбеддинги эмоций речи

* Репозиторий:
  [https://github.com/speechbrain/speechbrain](https://github.com/speechbrain/speechbrain)
* Готовые рецепты:

  ```text
  recipes/RAVDESS/emotion_recognition
  ```
* Плюсы:

  * современный Transformer;
  * предобучен;
  * хорошо ложится в мультимодальный фьюжн.

---

### 🔁 Альтернатива (проще)

**OpenSMILE**

* Репозиторий:
  [https://github.com/audeering/opensmile](https://github.com/audeering/opensmile)
* Плюс:

  * не требует GPU
* Минус:

  * устаревший подход

## 2.2 Что важно подчеркнуть на защите

* каждая модальность обрабатывается **независимо**;
* модели **предобученные**;
* обучение проводится **только на fusion-слое** (или вообще не проводится);
* система модульная.

# 3. Минимальный вариант под защиту (РЕКОМЕНДУЕМЫЙ)

Это **самый важный пункт**.

## 3.1 Что делать НЕ НУЖНО

* не нужно обучать CNN с нуля;
* не нужен полноценный мультимодальный Transformer;
* не нужен real-time стриминг;
* не нужны сложные attention-механизмы.

---

## 3.2 Минимально достаточная конфигурация

### Видео

* OpenFace 2.2
* Извлекать:

  * AU-интенсивности
  * уверенность
* Агрегация:

  * mean / max по времени

### Аудио

* OpenSMILE **или** готовый Wav2Vec inference
* Извлекать:

  * pitch
  * energy
  * speech rate

### Фьюжн

* Простая модель:

  * Logistic Regression
  * или RandomForest
* Вход:

  * concat(video_features, audio_features)

### Выход

* 3 класса:

  * низкий стресс
  * средний стресс
  * высокий стресс

---

## 3.3 Почему это легко защитить

| Критерий           | Почему хорошо      |
| ------------------ | ------------------ |
| Интерпретируемость | AU и pitch понятны |
| Воспроизводимость  | open-source        |
| Ограниченность     | нет переобучения   |
| Академичность      | классическая схема |
| Реализм            | применимо в HR     |

---

## 4. Как это связать с физической моделью

* `video_stream` → OpenFace → `emotion_record`
* `audio_stream` → Wav2Vec → `emotion_record`
* `emotion_analysis_config` → фиксирует пайплайн
* `report.dashboard_json` → визуализация

---

## 5. Рекомендованный стек (коротко)

* Python 3.10

* OpenFace 2.2
* SpeechBrain / OpenSMILE
* PostgreSQL
* FastAPI (опционально)

---

## 6. Формулировка для защиты

> Для обеспечения воспроизводимости и снижения вычислительных затрат в работе используется ансамблевый мультимодальный подход на основе предобученных моделей. Анализ видеопотока выполняется с применением библиотеки OpenFace для извлечения интерпретируемых признаков выражений лица, а анализ аудиопотока — с использованием предобученной модели Wav2Vec 2.0. Интеграция признаков осуществляется на уровне fusion-слоя, реализованного в виде простой классификационной модели, что позволяет получить устойчивые HR-метрики без необходимости полного переобучения нейронных сетей.
